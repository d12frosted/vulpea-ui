#+title: Changelog

All notable changes to this project will be documented in this file.

* Unreleased

** Added

- Collection view: =M-x vulpea-ui-collection= opens a sortable table over a filtered set of notes - a lightweight Airtable for the collection ([[https://github.com/d12frosted/vulpea-ui/issues/15][#15]]). A view is a plist of =:filter= (tags all/any/none, level, directory, title regexp, meta conditions, arbitrary predicate - the cheapest condition is pushed down to the database, the rest applied in memory), =:columns= (title, tags, =(meta KEY)=, created, modified, outgoing link count, backlink count via one grouped query, file) and =:sort=. Views are saved in =vulpea-ui-collection-views= and offered with completion; free input like =wine, rated= opens an ad-hoc view over those tags, empty input opens everything, and =w= saves the current view. The table is =tabulated-list-mode=, so sticky header, click-to-sort and column widening come for free; rows are marked dired-style (=m=/=u=/=U=/=t=), marks are keyed by note id so they survive sorting and re-querying, and bulk actions apply to the marked notes or the note at point: add/remove tag (=+=/=-=), set/remove a metadata field (=e=/=E=), delete note files with confirmation (=D=, heading-level notes are skipped), or any function on the selection (=x=). Tag and metadata edits go through vulpea's batch operations. Like the sidebar, the view refreshes when background extraction lands data, coalescing bulk syncs into one refresh.

- The collection view is shaped from inside the buffer. The =/= prefix refines the filter step by step - require or exclude a tag, match titles against a regexp, scope to a directory, condition on a metadata field (a value or its mere presence), pick a level, or clear everything - and the =c= prefix manages columns, completing over the built-ins plus a =meta:KEY= entry for every metadata key found on the notes in the view. =?= opens a transient menu with every command the view has, headlined by the view name, note count and active filter; the same summary lives in the mode line (=:4231 (3 marked) [#wine -#beer]=), so the buffer always tells you what you are looking at. transient ships with Emacs 28+, so this adds no dependency.

- Marking is instant on large collections: a single =m= used to go through the table's full re-print machinery, which walks and diffs every line of the buffer - unusable around 4k notes. A mark now rewrites only its own row (marks still survive sorting, they live in the entries themselves).

- The collection view reads like a table, not a text dump. New columns from data the note already carries: =context= (file title and outline path, so a dozen heading notes all called "Tasks" tell themselves apart), =todo=, =priority=, =scheduled=, =deadline= and =aliases=. Column widths fit the content (the old defaults act as caps, explicit =:width= still wins), hand-resized columns keep their width across refreshes and get pinned into the view on =w=, tags/dates/context/todo columns carry muted or org-derived faces, marked rows are highlighted across every cell, =hl-line-mode= tracks the current row, and an empty result shows a hint instead of a blank buffer.

- Working through a big view: =o= visits the note at point in another window and =C-o= previews it without leaving the table; =m=/=u= act on the active region; =% m= marks by title regexp and =% t= by tag; =/ k= removes a single filter condition (completing over the active ones); =y= copies the selection as an org list of id links and =Y= exports it to an org buffer; bulk tag/meta edits on more than one note ask first and list the affected notes.

- Collection housekeeping: buffers are bookmarkable (=C-x r m= records the view, jumping re-opens it), saved views can be renamed and deleted, and hidden collection buffers no longer re-query on every database change - they go stale and refresh when displayed again.

- The collection view edits in place. =e= is context-aware: on the tags column it rewrites the tags of the note at point (completion, prefilled); on a meta column it reads a value for that key - prefilled from the note at point - and sets it on the selection; anywhere else it prompts for a key as before. =Z= undoes the last batch edit, one level deep and precisely: adding a tag only strips it from notes that gained it, removing one re-adds it only where it was, and meta edits restore each note's previous values (removing keys that were absent). Deleting files clears the record - that cannot be replayed.

- Ad-hoc collection input is a full query language now, not just tags: =wine -beer #red? level:0 dir:cellar title:^Ch country:France rating:*=. The syntax is exactly what the mode line prints as the filter summary, so the description you see is a query you can type. =/ s= narrows titles live as you type (quitting restores the previous filter), and numeric meta columns get their average in the mode line (=:142 {rating avg 8.4}=), computed once per refresh.

- Collections grew Airtable-style grouping: =G= groups rows by any column's value - tags, a meta field, todo state - with a header and count per group, saved as part of the view. Built on the tabulated-list grouping that arrived in Emacs 30 (a clear error on older Emacsen).

- Default columns are adaptive. A view without =:columns= used to show title, tags and modified - the modified date is file mtime captured at sync, so a bulk operation stamps everything with the same day, and heading notes all inherit their file's date; tags were often empty air. Columns are now derived from the notes being shown, so empty ones never appear: title always, context when heading-level notes are present, tags and todo when some note carries them, and the backlink count (numeric sort - one click to surface hub notes). Ad-hoc views come sorted by title instead of arbitrary database order. Set =vulpea-ui-collection-default-columns= to an explicit list to opt out.

- Drill-down and inspection at point. === adds a filter condition from the cell under point - the Airtable right-click-to-filter gesture: a tag from the tags column, a meta cell's value, a todo state, or the note's directory from the context and file columns (the filter language grew a =todo:= condition for this, round-tripping through the mode line summary, the query parser and =/ k= removal). Hovering a truncated cell shows its full value as a tooltip, and =SPC= prints the whole row as =column: value= lines - closing the ticket's hover/expand bullet. The mode line also shows the filter's bite (=:142/4231=) instead of the bare match count.

- Batch todo states. =T= sets a state on the selection's heading-level notes via =org-todo= in each note's own buffer, with completion over =org-todo-keywords-1= and empty input clearing the state; file-level notes are skipped and =Z= restores the old states per note. The todo column now sorts in org keyword order instead of alphabetically, so DONE stops floating above TODO.

- A collection view benchmark joins the dashboard render bench in =bench/=: entries building, full render and 100 single marks at 1k/5k/10k fabricated notes. The mark figure guards the O(1) mark path - at 10k notes a mark is ~60 us.

- Collections reach beyond their own buffer: saved views show up as a =Collections= sidebar widget (one click from any note to a view, hidden while no views exist), and any view can be embedded in a note as an org dynamic block - =#+BEGIN: vulpea-collection :query "wine rating:*" :columns (title (meta "rating"))= renders an org table with =id:=-linked titles, registered with =org-dynamic-block-define= so =C-c C-x x= offers it.

- Auto-refresh understands vulpea's async extraction (vulpea 2.6+). The database changes when the background worker applies results, not when a file is saved, so the save-triggered refresh alone showed pre-save data until the next manual refresh. The sidebar now also refreshes when background extraction lands (vulpea's =vulpea-db-worker-done-functions= hook); during bulk syncs the refreshes coalesce into a single one when the burst drains, so a 10k-note rebuild does not become a refresh storm. No-op on vulpea versions without async extraction.

- The schema health widget now reports on *every* note in the file, not just the one the sidebar is anchored on. A heading with its own =:ID:=, tags and metadata is a note in its own right, so a file often holds several: the file-level note plus one per heading. With a single schema-bearing note the widget reads exactly as before; with several it breaks the file down per note - the file-level note first, then headings in document order - each violated note under its title (a keyed button that jumps to it), with a trailing =✓ N notes healthy= count for the clean ones. Each violation's =fix= button writes back into *that* note (a heading's field lands in the heading's subtree, via vulpea's =bound= argument), and the buttons carry note-scoped keys so point rides its row across a fix even when notes above it clear. The widget hides only when no note in the file bears a schema.

- Support files whose IDs live only on headings. =vulpea-ui--get-note-from-buffer= now falls back to the earliest heading-level note (by position) when a file has no file-level =:ID:=, so heading-only files anchor the sidebar and light up the schema widget instead of showing nothing. Files that do have a file-level ID are unaffected.

- =vulpea-ui-schema-health-note-face= (inherits =bold=) for a note's title in the per-file breakdown.

** Fixed

- The schema health widget and the schema dashboard now jump to the right line for a field that fails =:one-of= on more than one of its values. =vulpea-ui--schema-violation-position= matched on the field name alone, so each disallowed value of a multi-value field jumped to that field's *first* line; it now prefers the line carrying the offending value, falling back to the first occurrence when the value cannot be matched textually.

- The schema health widget was blind to heading-level notes: it always resolved the file-level note and reported only that one's schema, so a violation on an =:execution:= heading inside a schema-less =:journal:= file was invisible in the sidebar (the counterpart, on the authoring side, to [[https://github.com/d12frosted/vulpea/issues/356][vulpea#356]]). It now looks at the whole file, so heading violations surface regardless of where point sits. The lower-level scoping helpers (=vulpea-ui--schema-note-end=, =-meta-position=, =-violation-position=) were already heading-aware but had never been exercised on a heading; they now have coverage.

* v1.2.0 (2026-07-02)

** Added

- Fix violations straight from the schema dashboard. Invalid notes now start collapsed and expand to their individual violations, each row showing the field and a terse reason alongside a =fix= button (the per-note widget's view, one level deeper). Fixing pops the note open at that field only while the prompt (via vulpea's =vulpea-schema-fix-violation=) is open, then writes the value, re-indexes, refreshes, and restores your previous window layout so you land back on the dashboard; you see what you are fixing and where, and can fix or skip each one on its own; the field name jumps to the note without fixing. The =fix= button shows only when the running vulpea provides the fixer. Schema and note headers use =vui-flex= to right-align their counts ([[https://github.com/d12frosted/vulpea-ui/issues/16][#16]]).

- Schema dashboard, a collection-wide =M-x vulpea-ui-schema-dashboard= view in a =*vulpea schema*= buffer (not the sidebar). It lists every registered schema with how many notes it covers and how many are invalid, sorted so the schemas needing attention come first and unused ones sink to the bottom, with =:include= relationships annotated both ways (=includes= / =included by=). Each schema is collapsible and those with violations start expanded; expand one to see its invalid notes as clickable links that jump to the note, where the health widget and quick-fix actions take over. =g= rescans, =q= buries the buffer. Built on vulpea's =vulpea-schema-collection-health=, so the scan is one query plus an in-memory pass and stays fast on large collections ([[https://github.com/d12frosted/vulpea-ui/issues/16][#16]]).
- Quick-fix actions in the schema health widget. Each violation row gets a =fix= button that prompts for a corrected value - =:one-of= completion, note selection honouring =:target-tags=, multi-value fields - and writes it back via vulpea's =vulpea-schema-fix-violation=, then saves the note, re-indexes it, and refreshes the sidebar so the fixed violation clears. The button only shows when the underlying vulpea provides =vulpea-schema-fix-violation= (an older vulpea still renders the row, just without the button), and it is styled with the new =vulpea-ui-schema-health-action-face= ([[https://github.com/d12frosted/vulpea-ui/issues/38][#38]]).
- Schema health widget: a per-note "is this note healthy?" view in the sidebar. When the current note matches one or more schemas it shows a green =healthy= line if the note conforms, or its violations otherwise - each a severity-coloured bullet (red for structural problems like a missing field, a wrong type or a bad reference; amber for value problems like a disallowed value, a failed =:validate= or a bad target), the field name, and a terse reason (="required"=, ="not one of red/white/rose"=, ="expected a number"=). It hides entirely when no schema applies, the same graceful-empty behaviour as the stats widget. Glyphs (=vulpea-ui-schema-health-ok-glyph=, =-issue-glyph=, =-bullet=) and the inheriting faces are customizable. Built on vulpea's schema engine (=vulpea-schema-note-violations=, =vulpea-schema-applicable=); clicking a field jumps to it in the note (a missing field jumps to the metadata block, where it would be added), and quick-fix editing actions are tracked in [[https://github.com/d12frosted/vulpea-ui/issues/38][#38]] ([[https://github.com/d12frosted/vulpea-ui/issues/29][#29]]).
- Unlinked mentions widget showing notes that mention the current note's title or aliases as plain text without an =id:= link back. It is the sidebar's first asynchronous widget: the search is delegated to =vulpea-note-unlinked-mentions-async= (ripgrep) and rendered via =vui-use-async=, so it shows a loading state, fills in when results arrive, and caches them until the note changes or the sidebar is refreshed. Requires [[https://github.com/BurntSushi/ripgrep][ripgrep]] and vulpea 2.4.0+ ([[https://github.com/d12frosted/vulpea-ui/issues/13][#13]]).
- Outgoing mentions widget, the counterpart to the unlinked mentions widget: it shows existing notes that the current note mentions as plain text *without* an =id:= link to them - the notes you may want to link out to. Suggestions are grouped by the note you could link to, and clicking a context line jumps to the mention in the current note. Like the unlinked mentions widget it is asynchronous: the search is delegated to =vulpea-buffer-unlinked-mentions-async= (ripgrep, scanning the note's live buffer so unsaved edits count) and rendered via =vui-use-async=, with a loading state and results cached until the note changes or the sidebar is refreshed. Requires [[https://github.com/BurntSushi/ripgrep][ripgrep]] and vulpea 2.4.0+ ([[https://github.com/d12frosted/vulpea-ui/issues/33][#33]]).
- Presentation-only note filters for both mention widgets: =vulpea-ui-unlinked-mentions-note-filter= and =vulpea-ui-outgoing-mentions-note-filter= (both default =identity=) take a predicate on the note and drop non-matching mentions before display, mirroring =vulpea-ui-backlinks-note-filter=. Handy for hiding e.g. index notes from suggestions without touching the collection-wide =vulpea-mentions-note-filter= ([[https://github.com/d12frosted/vulpea-ui/issues/33][#33]]).
- Quick-link actions in the outgoing mentions widget. Each suggestion has a =link= button (before the context) that rewrites that plain-text occurrence in place as an =id:= link, and each note group has a =link all= button that links every occurrence for that note at once. Linking re-validates against the live buffer before editing (matching the note's title or aliases word-bounded and case-insensitive, skipping occurrences already inside a link), so a stale or already-linked suggestion is a no-op. It keeps point where it is and does not auto-refresh, so you can link several in a row without losing your place; press =g= to update the list. The new =vulpea-ui-mention-action-face= styles the buttons ([[https://github.com/d12frosted/vulpea-ui/issues/33][#33]]).

** Changed

- Raise the minimum dependencies to vui 1.3.0 and vulpea 2.5.0. This release's schema views - the schema dashboard, the per-note schema health widget and the quick-fix actions - are built on vulpea 2.5.0's schema engine (=vulpea-schema-collection-health=, =vulpea-schema-note-violations=, =vulpea-schema-applicable=, =vulpea-schema-fix-violation= and the =vulpea-schema-health= struct), and the dashboard's cursor-stable collapsibles, the move off =widget.el= accessors onto vui's public element API (=vui-element-at=, =vui-element-get=, =vui-key-at=, =vui-activate=, =vui-goto-key=) and =vui-collapsible='s =:header-right= / =:header-width= all landed in vui 1.3.0. The schema code still =fboundp=-guards its vulpea entry points, so a stale vulpea degrades gracefully instead of erroring, but 2.5.0 is what the new views actually need.

Thanks =@darcamo= for the suggestion.

N)= cons, or a window-adjusting function - and point at Info node =(elisp) Buffer Display Action Alists=. Thanks =@drcxd= for the docstring and the change ([[https://github.com/d12frosted/vulpea-ui/pull/44][#44]]).

** Fixed

- Work with vui's text-button rendering again. vui now renders buttons as =button.el= text buttons rather than =widget.el= widgets, so my old =widget.el= accessors (=widget-at=, =widget-get=, =widget-apply=) came up empty on them and the schema dashboard code and tests broke. Migrated the one code path and the tests onto vui's public element API (=vui-activate=, =vui-key-at=, =vui-element-at= / =vui-element-get=), which hides the rendering mechanism, so vulpea-ui no longer cares whether an element is a button or a widget.
- Keep point where it is when toggling or refreshing the schema dashboard. The section and note headers were hand-rolled buttons with the ▶/▼ indicator baked into the label and no key, and the violation rows carried a =fix= button (the same label on every row) and field buttons with no key, so on a toggle, a =g= refresh, or an after-fix refresh cursor restoration could not re-find the widget point was on and point jumped to the top of the buffer. The dashboard now builds on =vui-collapsible=, which gives every toggle a stable cursor identity across the ▶/▼ flip and right-aligns the count/status to the window edge via its new =:header-right= / =:header-width=; the fix and field buttons carry keys that stay unique even when the same note is invalid under more than one schema, so point rides its widget across toggles and refreshes instead of falling to the top ([[https://github.com/d12frosted/vulpea-ui/issues/16][#16]]).
- Keep point in place after fixing a violation from the schema dashboard. A fix removes the row point sat on (and, once it was the note's last issue, the whole note), so there was no widget left for cursor restoration to return to and point dropped to the top of the buffer. vui recovers point to the nearest surviving row in the component tree, but only when point is on a widget when the buffer redraws, and clicking the =fix= button with the mouse does not move point, so it could be sitting on the summary line at the top, which vui faithfully keeps. So the fix action now anchors point on the note it just fixed before refreshing, and vui recovers from there to the note that slid into the fixed one's place, or the previous note in the same section once you clear its last one, so you stay where you were working inside that section instead of jumping to the top or down into the next schema ([[https://github.com/d12frosted/vulpea-ui/issues/16][#16]]).
- Keep point in place when refreshing the sidebar with =g=. The mention widgets re-scan asynchronously, and a refresh used to blank them to their loading state, so the buttons point was on disappeared and the cursor fell back to the top of the sidebar. They now keep the previously loaded list on screen while the re-scan runs (cached per note via a ref), so the widget structure stays stable and point is preserved. Applies to both the unlinked mentions and outgoing mentions widgets ([[https://github.com/d12frosted/vulpea-ui/issues/33][#33]]).
- Stop treating other side windows (e.g. a =*Help*= or =*Info*= buffer that the user's =display-buffer-alist= pins to a side) as the main window. =vulpea-ui--get-main-window= now skips any window with a =window-side= parameter, so merely focusing such a window is no longer mistaken for switching away from the vulpea note. Previously this triggered an auto-hide/re-show of the sidebar on every focus change; combined with =window-combination-resize=, the repeated delete/recreate of the side window steadily shrank the note window until it collapsed ([[https://github.com/d12frosted/vulpea-ui/issues/36][#36]]). Thanks =@drcxd= for the report.
- Display the sidebar even when the user disabled side windows on its configured side via =window-sides-slots= (e.g. ='(1 0 0 1)= to forbid right-side windows). Previously =display-buffer-in-side-window= returned nil, the sidebar buffer silently took over the selected window, and a follow-up auto-hide attempt errored with "Attempt to delete ... sole ordinary window". A local copy of =window-sides-slots= now guarantees the sidebar's side at least one slot ([[https://github.com/d12frosted/vulpea-journal/issues/21][vulpea-journal#21]]). Thanks =@drcxd= for the report.
- Only delete the sidebar window when it is a real side window. =vulpea-ui--hide-sidebar-window= (used by auto-hide and =vulpea-ui-sidebar-close=) now leaves a regular window untouched instead of deleting a main or sole window, hardening teardown against the error above ([[https://github.com/d12frosted/vulpea-journal/issues/21][vulpea-journal#21]]).
- Skip rendering the sidebar when the frame has no live side window. Because mounting calls =switch-to-buffer=, a render attempt without a side window used to replace the selected window's buffer with the sidebar; =vulpea-ui--render-sidebar= now bails out instead of clobbering an unrelated window ([[https://github.com/d12frosted/vulpea-journal/issues/21][vulpea-journal#21]]).
- Guard =mode-line-invisible-mode= call with =fboundp= since it is only available starting from Emacs 31.
- Suppress inline image and LaTeX previews in parsing temp buffers, fixing crash when sidebar encounters notes with =attachment:= links and =#+startup: inlineimages= ([[https://github.com/d12frosted/vulpea-ui/issues/21][#21]]). Thanks =@eamonnsullivan= for the report.
- Use =org-inhibit-startup= instead of individual variable suppression in parsing buffers, fixing crash when buffer-level =#+startup: inlineimages= keyword overrides let-bound variables in newer Emacs/Org versions ([[https://github.com/d12frosted/vulpea-ui/issues/23][#23]]). Thanks =@eamonnsullivan= for the follow-up report.
- Strip org markup from outline heading titles so links and similar constructs no longer show as raw markup in the outline ([[https://github.com/d12frosted/vulpea-ui/issues/20][#20]]). Thanks =@evertedsphere= for the report.

* v1.1.0 (2026-01-31)

** Fixed

- Preserve collapsible section state during automatic refresh. Previously, collapsed widgets would reset to default state on idle/save refresh.
- Eliminate sidebar flicker during idle refresh. Idle timer now uses soft update (=vui-update-props=) preserving memo caches — only widgets whose deps changed (stats/outline via =buffer-modified-tick=) recompute. Save and manual refresh still invalidate all caches.
- Outline widget now reads from buffer when available (like stats), enabling live heading updates while editing.
- Remove unused =vulpea-ui-backlinks-preview-lines= defcustom.
- Apply =vulpea-ui-backlink-context-face= to context indicator characters (previously unused).
- Deduplicate =vulpea-ui-widget-toggle-at-point= implementation.

** Changed

- Reimplement =vulpea-ui-widget= using =vui-collapsible= from vui-components internally. The public API remains unchanged.
- Use =vui-muted= semantic component for de-emphasized text.
- Enable =mode-line-invisible-mode= in sidebar by default for a cleaner UI. Can be toggled off if needed.

* v1.0.0-rc.1 (2025-12-12)

First release candidate.

** Features

- Per-frame sidebar with configurable position and size
- Widget system built on [[https://github.com/d12frosted/vui.el][vui]] components
- Widget registration system with predicates for context-aware display
- Default widgets:
  - *Stats* - character count, word count, link count
  - *Outline* - heading structure with navigation
  - *Backlinks* - notes linking to current note, grouped by heading with context previews
  - *Links* - forward links from current note
- Backlinks features:
  - Group by heading with clickable previews
  - Context type indicators (meta, header, table, list, quote, code, footnote, prose)
  - Configurable filtering by note and context type
  - Sorting options (title ascending/descending or custom)
- Auto-hide when switching to non-vulpea buffers
- Fast-parse option for performance optimization
- Easy API for creating custom widgets

** Dependencies

- Emacs 29.1+
- [[https://github.com/d12frosted/vulpea][vulpea]] (v2)
- [[https://github.com/d12frosted/vui.el][vui]]
